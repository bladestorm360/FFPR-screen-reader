## Architecture and reverse engineering evidence

Record functions/signatures, callers, view fields, flags, lifetime/hook constraints and analysis provenance here as confirmed. Metadata only confirms existence/signature, not displayed-data behavior. Native decompilation and extracted prefab/scene assets are needed for renderer parity.

### Native battle and UI evidence

- Name/signature manifests and matching metadata are in [re](re/). Read-only headless Ghidra uses the existing FF2/FF5 analysis projects, `-process GameAssembly.dll -noanalysis -readOnly`, and [DecompileManifest.java](../tools/re/DecompileManifest.java), with no analysis or decompile timeout. Local C exports/logs are analysis artifacts, not distributable game source.
- `Last.Management.SubSceneManagerMainGame.ChangeState(State)` is unique in all six dumps; Battle = 13, field states = 0–4, GotoTitle = 14. FF2 RVA `0x797910`, FF5 `0x4EE630`. It dispatches the native state machine and UI visibility group. Core now enters battle before that dispatch, and retains battle context through results/fade until native field/title return. Command and menu hooks remain idempotent fallbacks.
- `Last.UI.KeyInput.BattlePlayerInfomationController.UpdateView(players, isTarget)` swaps ordinary `contentList` and `targetSelectContentList`. Both views render `nameText`, `currentHpText`, `maxHpText`, `currentMpText`; there is no maximum MP text in these battle rows. HP setters populate two Text fields; MP setter populates the current value only. Shared H/T/number readers use the active rendered panel. Shared actor state survives command menu reset. The previous H reader duplicated that reset and could clear its owner on submenu entry.
- `ItemTargetSelectContentView.UseHp/UseMp` independently enable their label/current/maximum/separator components. FF2 RVAs `0x7C7B40`/`0x7C7EF0`; FF5 `0xA1D170`/`0xA1D520`. Target reads now use enabled native components instead of unconditional parameter HP/MP/status lists.
- Native result outer phases activate controller state machines; their inner pages populate later. Core now reads inner `ResultPointController.PointsInit` and per-member `ResultStatusUpController.SetData`, with a single event-owned next-frame read. FF2 `StatusUpInit` (`0x3DA240`) builds its status-up list and advances one member at a time; `SetData` (`0x3DB950`) fills only that page. The old reader flattened all characters from `BattleResultData`.
- Result comparison views include category, before/after, multiplier and percentage components (FF2 evasion/accuracy), job labels and native magicite bonus fields (FF6). Core reads visible rows, not a universal stat enum. Learned ability/job panels are read where actually visible, including combined points/skill panels and native ability page changes. FF5/FF6 early raw reward/learning extensions have moved into core.
- Central [displayed_ui](../src/core/displayed_ui.cpp) checks Unity lifetime, active hierarchy, component enabled, Graphic alpha, CanvasRenderer culling and inherited alpha. Text fields, bars and reconstructed sprite/icon descriptions share this gate; missing fields never substitute hidden parameter data, except for the explicitly approved optional enemy HP disclosure documented below.
- Hit-counter caller scans in [all-six evidence](re/hit_counter_callers.txt) find the native sprite counter chain in all six binaries; existence alone does not establish which attacks display it. FF2 `HitCountEntity.SetNumSprite` (`0x4920B0`) renders the exact count as digit sprites; `SetHitSprite` (`0x491E70`) chooses singular/plural. Core reads only an instantiated, visibly rendered counter, separately from the displayed damage total. An event-owned bounded 30-frame wait accommodates fade-in; no counter is inferred from damage or game number. Existing status/action-message guards are preserved.

### Route arrival evidence

- User added 2026-10-11: Backslash should give the direction to any adjacent interactible/NPC; do not append facing to an unfinished route. The previous `remaining_from` discarded `action_after` when cropping a kept route, producing “No movement needed” on arrival. `route_progress::remaining` preserves end instructions, while `arrival_facing` is presented only for the final one-cell phase. Facing is retained even when the final movement was already in that direction. Offline regression expectations cover arrival, intermediate corners and leaving the route.

### Thread/lifetime findings

- Reference self-check/warmup now runs before live hooks are applied: reference caches are lock-free and must not be mutated concurrently by boot and the game thread.
- Scheduler cancellation now marks running tasks cancelled and holds a copy of an executing callback until it returns. Previously cancelling a running `every_frame` task overwrote and destroyed that task's executing closure.
- Boot thread handle is closed after creation; no wait or game work is added inside `DllMain`. IL2CPP/UI reads stay on native hooks/the main-thread frame dispatcher. Performance measurements remain user-side; no game was started.

### Additional evidence and corrections

- FF2 native `ConditionIconController.UpdateView` (`0x5354D0`) resets icons, selects native `GetIcon` (`0x535250`) sprites, and activates only slots actually populated. The shared icon reader captures those native selections without extra enumeration/asset lookups, then requires a visible matching Image. Icon descriptions never fall back to a parameter condition list. [Manifest](re/ff2_rendericons_manifest.tsv).
- All six field spell target readers now use the same displayed target utility as item targeting. HP/MP components independently control speech; status icons require renderer proof. FF4/FF6 party split views also use visible Text rather than raw HP/MP/level parameters.
- Enemy target information views contain only name/count/focus fields in matching dumps. Hidden parameter status suffixes remain excluded. On 2026-10-11 the user explicitly authorized retaining the legacy optional HP disclosure: Numbers appends `: HP current/maximum`; Percentage appends `: remaining%`; Hidden appends nothing and does not read parameters. The central `battle::optional_enemy_hp` serves all six games. Existing `EnemyHPDisplay` preferences and default 0 are preserved; F5 cycles the three modes in battle and the Battle submenu explains that the native panel does not display these values. This is a scoped exception for enemy HP only. Scan/Libra remains spoken through native displayed result messages.
- Native `FieldColliderEntity.CanEnter` (FF2 `0x7E1900`) lets collider type 6 pass horizontal movement and type 7 pass vertical movement. Routing now stores these as directional constraints, shared by A* and flood search.
- FF6 `ViewDamageEntity.CreateDamageValue` has a **five-argument** native signature, including Vector2 damage offset; FF1–FF5 have four. Corrected the per-game detour ABI. FF1/FF3 have no `ResultSkillController.UpdateContentPage`, so that hook is masked to games that actually define it.
- The result EXP monitor now compares `performanceList.Count` with `perormanceEndCount`, matching native `IsEndPerformance`, and native completion refreshes final displayed member values. Result entry waits are bounded and event-owned, allowing fade-in before reading.
- The scheduler clock frequency is now an immutable, thread-safe local static. Builds use four compiler/MSBuild workers rather than unconstrained nested parallelism. These are offline stability/cost corrections; game load time and gameplay frame timing remain unmeasured.

### Map state, topology and conservative boundaries

- [bake_maps.py](../tools/bake_maps.py) round-trips six grids/object sets. Native None and Stamp
  move types remain stationary. Twelve FF2 Dreadnought captains retain collision after battle;
  the regression routes native PointIn 1 to engine-room exit 175 around the room on Bottom layer 0.
- [bake_map_state.py](../tools/bake_map_state.py) extracts initializer branch/flag/group decisions
  and treasure flag IDs only. No dialogue, battle outcomes or native script execution.
  [map_state_program.cpp](../src/core/field/map_state_program.cpp) evaluates copied flags with
  private shadow writes. Unknown locals fork both ways; a group is accepted only if every
  completed branch agrees. Stack, branch and instruction budgets fail closed.
- `Last.Interpreter.DataStorage`: scenario/treasure `Flags.bits[32]`, length 1024, and 16 global
  integers. `MapUIManager.GetFlag` uses `flag_id / 256` and `flag_id % 256` directly. Native
  comparison jumps to iValues[2] when true. FF2 evidence: crossfloor/flag_arrow manifests in
  [re](re/). `FieldController.SetEventEntityGroup(string)` records the actual current group
  and invalidates routes immediately.
- FF1 `Current.MapEntryRoofControl(MainCore)`, RVA 0x59B460, calls IMapAccessor slots 10
  (`SetMapLayerEnabled`) and 20 (`SwitchMinimapIconLayerEnable`), reading player Z. It does not
  write flags/select groups; this exact FF1 call is omitted from group projection. Other
  SysCalls remain conservative. Evidence: ff1_roof/ff1_roof_calls manifests and IMapAccessor ABI.
- Future-floor routes apply selected groups, collected-chest flags, solid NPCs/gates and
  directional colliders. An exit cannot become a graph edge through a blocked tile. Unknown
  variant destinations stay excluded; possible blockers remain solid. Future puzzle actions
  and changes to story flags are not predicted.
- Quick filters ignore event hazards while retaining physical collision. Explicit routes
  first avoid events; required triggers remain routable with `Event trigger on the route.`
  Cached-route cropping preserves facing, spoken only after movement ends for every interactible.
- Spoiler-free inference records: [EVENT_LABELS.md](EVENT_LABELS.md).

### Thread ownership and costs

- Boot resolves/self-checks references and warns about an old mod before enabling hooks,
  preventing startup cache/language races. It detaches from IL2CPP before loader waits.
  DllMain never waits on it; its OS handle closes; supported/unsupported exits detach safely.
- UI/game pointers and IL2CPP calls stay on the game dispatcher. Tolk uses its existing worker
  queue. Cross-thread posts swap under an SRW lock; callbacks run outside it. Cancellation marks
  a running task without destroying its closure; nested tasks start next tick.
  [frame_check.cpp](../tools/frame_check.cpp) checks lifetimes and 1,000 concurrent posts offline.
- Renderer reads start from native UI events. Bounded readiness retries stop on visibility,
  generation changes, phase exits and battle/scene cancellation. EXP progress checks run only
  during that animation. Map-state JSON is now prepared on the background data worker
  ([user-test follow-up](FOLLOWUP_2026_10_11.md)); each route copies flags
  once and memoizes floor selection. No new whole-scene per-frame scan was introduced.
- Import/export and hook coexistence tests protect native loading. Offline checks establish
  ownership and code paths, not measured startup overhead/frame times; those need user observation.

### Shared presentation and per-game features
