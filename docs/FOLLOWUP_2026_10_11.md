# October 11 popup, loading and route follow-up

Owner: Sol. This follows the completed [audit](AUDIT_2026_10.md). User reports come
from FF2; the implementation is shared by FF1–FF6. No game was launched or controlled.

## Popup body regression and coverage

The scheduler copied a mutable `std::function` before every invocation. Its captured
readiness counter consequently restarted at zero every frame. Save confirmation
readers never reached their required second frame, while the independent Yes/No
focus hook still worked. `frame.cpp` now moves the closure out while executing and
restores it only if the task continues. This preserves state and self-cancellation
lifetime. Offline regressions verify the actual two-frame reader pattern, successive
mutable state, nested work, cancellation and 1,000 concurrent main-thread posts.

`dialogue::read_popup_when_ready` is the shared bounded presentation reader. It waits
for a live current popup and rendered text, speaks the body on entry, and cancels on
close/replacement. Save completion follows native title text when messageText is
actually empty; it does not mistake an unrendered pending body for completion.
An older popup's close cannot cancel a newer popup's reader. Existing button-focus
guards/deduplication remain in their original producer paths; no speech deduplication
was added.

The six metadata dumps have the same relevant PC popup families:

| Native family | Shared coverage |
| --- | --- |
| SavePopup | Title/game load, save/overwrite, quicksave and completion body/submessage/focused button via existing controller state hooks |
| CommonPopup | Return to title, quit, confirmations, notices and displayed image-caption text; native button focus |
| InfomationPopup, InputPopup, ChangeNamePopup | Rendered title/message or description via Popup.Open |
| ChangeMagicStonePopup | Rendered name/description and native command list |
| GameOverSelectPopup, GameOverLoadPopup | Native phase body and their existing button-focus readers; load popup is a separate MonoBehaviour |
| JobChangePopup and remaining Popup subclasses | Rendered non-button text; job confirmation retains its native command-list button reader |
| Serial.FF1/FF2/FF3 NewGamePopup | Actual rendered message at InitStartPopup, replacing old fallback/get_Message paths |
| PlayDataPopupController | Rendered text on its own Open event; does not inherit Popup |
| WarehousePopupController | Rendered storage quantity prompt/view on Show; does not inherit Popup |

The old shop-wide early return was an active but overbroad guard, not dead code:
it silenced any legitimate Popup opened while ShopController.IsOpne was true.
Shop trade has its own MonoBehaviour reader. The popup reader now follows the actual
popup type and visibility rather than excluding all popups in that context.

Representative native control flow was confirmed with the existing FF2 Ghidra project,
read-only, no reanalysis/time limit (`tools/re/DecompileManifest.java`). FF2 addresses:

- CommonPopup.Open: RVA 0x2D4860; calls base Popup.Open (0x6587D0), then places the cursor.
- JobChangePopup.Open: 0x7D3850; likewise calls base Popup.Open before setting its cursor.
- PlayDataPopupController.Open: 0x5B5640; enables itself, changes state and refreshes its displayed content list.
- WarehousePopupController.Show: 0x80F1F0; 7 arguments, fills view fields, then activates the view at self+0x50.
- TitleWindowController.SetEnableStartObject: 0x806340; activates view.startParent,
  but startup inlines it. The later title follow-up below corrects the original hook choice.

All referenced class/field/method names are checked against all six dumps by the build.
Presentation, fade timing and speech in a real game still require user confirmation.

## Map transition work and thread ownership

The user-run FF2 log showed a full entity scan scheduled after each additive UI scene
(CampMenu, SecondMenu, Battle and others), plus scans during ChangeMap before spawning
finished. These paths could both stall loading and publish an incomplete entity list.
The first baked-map open in that log occurred much later, on navigation input; baking
alone cannot explain the reported initial world-map delay.

Automatic scans now start only at native MainGame Player (3) or Transport (4), after
initialization. ChangeMap (1) invalidates the previous map, including same-map reloads.
SceneLoaded does not scan entities. It still handles audio/context resets; additive UI
completion can restore audio flags only if native field control is already ready.

One below-normal-priority native worker prepares the selected game's embedded JSON,
bake index and every decoded grid. Published data is immutable, with release/acquire
readiness. No grid/JSON decoding waits on the game thread. Future-floor projection
also runs on that worker from copied flag snapshots. No Unity object pointers enter
worker projection; the worker never attaches to IL2CPP or its garbage collector.

Unity entity reads and final native name lookup must remain on the game thread. Automatic
entity conversion and remote-entry formatting process at most 16 entries or 2 ms per
dispatch, checking time between entries. Snapshot collection and final list sorting
still occur on the owner thread. Generation cancellation rejects obsolete queued
work, and output is handed back through frame::post. A worker-start failure does not
silently fall back to a large synchronous projection.

Offline tests hold the worker behind an event while dispatching 100 frames, then verify
one main-thread publication and below-normal worker priority. All six bakes are fully
decoded in the map-state test and retain the same cached grid identities. These are
thread/logic checks and offline timings, not measurements of game transition latency.
Explicit manual refresh retains the existing synchronous incremental refresh contract.

User retest after deployment: startup was fast and map transitions were no longer slow.
The entering-map announcement now follows native field readiness after the transition;
the user explicitly accepted that timing. These are user observations, not agent runtime
measurements or a claim that every transition has been benchmarked.

## False event warnings

EventTriggerEntity is a base for ordinary GotoMap exits, layer switches and transportation
pads. The old live hazard collector accepted every active instance, so all FF2 world
entrances became purported story triggers even with an empty Events category.
Live story hazards now require native Event/RandomEvent object types and an active
trigger with actionable content. Ordinary exit/layer/vehicle objects are excluded.
The shared baked predicate retains script/action events and step-on warps, excluding
inert markers and examined-only warps.

Warning speech checks the actual route cells against applicable trigger footprints.
The occupied starting tile is not an upcoming event. Regression checks cover ordinary
world exits, layer/vehicle pads, inert markers, real events, step/examined warps,
wrong-layer triggers and the FF2 world route with no active hazards. Existing all-game
permanent-NPC and Dreadnought detour checks continue passing.

## Startup prompt and diagnostics

The first user-run FF2 boot installed only 33 hooks and failed 166, including title
and scene hooks. A subsequent boot installed 199 with zero failures. The earlier log
did not record the MinHook error code, so the exact first-boot failure is unresolved.
This is not evidence that slow/missed native-mod startup is normal first-run behavior.
Hook failures now record MinHook status and Win32 error. A 512-simultaneous-hook test
passes across multiple trampoline pages; the historical failure was not reproduced
in the isolated host.

The first follow-up changed the prompt hook to SetEnableStartObject. User retest found
that the prompt was then completely silent despite all hooks installing. Offline
investigation now confirms that all six native UpdateNone paths inline the activation
and never call that wrapper. The correction restores the actual contextual
SystemIndicator.Hide event immediately before parent activation, covers native
InitNone/InitShortcutCommand entry and cancels pending speech at InitSelect. It retains
the 60-frame rendered-text wait and interrupt priority without a hidden fallback.
[All-six native call paths and cinematic evidence](re/TITLE_PROMPT.md) document the
exact RVAs, producer events and independent offline checks.

For FF5/FF6 only, the visible game prompt is read verbatim first, followed by the
user-requested mod instruction: “Wait to watch the intro cinematic, or press a button
to open the title menu.” Their native demo idle timers and cinematic state remain
game-owned. Real speech/timing confirmation is still user-side.

FF2 also reported a stripped managed Renderer.get_isVisible wrapper. All six installed
UnityPlayer files contain the matching internal-call registration, and GameAssembly
exports il2cpp_resolve_icall. The shared visible-world reader falls back to that binding,
retaining renderer visibility rather than exposing invisible damage/hit parameters.
Unity's [renderer binding source](https://github.com/Unity-Technologies/UnityCsReference/blob/master/Runtime/Export/Graphics/GraphicsRenderers.bindings.cs)
confirms its boolean renderer visibility contract. Actual popup/damage visibility remains
gameplay-unconfirmed.

## Dead code removed and retained guards

Removed: unused save-popup markup helper and local retry constants, unused FF2/FF3
get_Message references, unused field-ready/player lookup declarations, old title
loading-indicator hook and controller-seen guard, and undefined battle suppression
query lookups. Battle suppression itself remains through the active native menu-state
flags. Existing popup ordering, renderer visibility, native readiness, cancellation,
identity and lifetime guards have live call paths and remain necessary. The title
follow-up removed the ineffective SetEnableStartObject wrapper hook and restored
SystemIndicator.Hide after verifying its live producer path in all six binaries.

Build/smoke/deployment verification is recorded in CODEX_MEMORY.md. User-side checks:
load confirmation body before Yes/No, save/quicksave/title/quit confirmations, title
prompt, repeated world/town/floor transitions, no event warning on ordinary FF2 world
routes, and navigation/audio after loading.
