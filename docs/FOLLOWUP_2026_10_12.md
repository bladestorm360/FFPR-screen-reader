## Shared naming implementation

`npc_names.h/.cpp` is a pure parser and group-numbering service. `Label` holds the descriptive
base and a separate numeric source ordinal. `Entry` holds the output string, label, floor/map
identity and snapshot coordinates. `renumber` groups by exact, case-sensitive base and numeric
map ID. Unique entries receive the base alone; duplicates receive `base1`, `base2`, etc.
Known source ordinals sort numerically before unknown ones, then snapshot coordinates provide
top-to-bottom/left-to-right order. Neither player distance nor a previously numbered output
string contributes to numbering. Both live and remote call sites use the same coordinate
ordering; each floor is independent. Groups are numbered before navigation filters.

`entity_translator.cpp::npc_display_label` normalizes a converted label and translates the
descriptive remainder exposed by nested prefixes. This preserves the existing initial
translation lookup for sprite-specific descriptions. `entity_scanner.cpp::renumber_npcs`
and `RemoteBuilder::step` call it and the central group service. The existing remote
story-variant identity guard is kept separately, with its original matching semantics.
No entity deduplication or filtering policy was added or expanded.

The exhaustive audit exposed and verified fixes for combined leading/trailing decorations
(`1兵士①`), nested FF6 script/NPC prefixes (`sc_e_0036:NPC11フィガロ兵`), and FF5/FF6
script suffixes. Script suffixes include bracketed or bare developer notes and ID ranges;
the descriptive name ends before the script reference. The one bare numeric NPC identifier,
FF6 `Map_20110`'s `NPC7`, receives the generic NPC descriptive fallback; its number stays
ordering metadata. Other empty-description/pure-number parser fallbacks remain conservative.
No other Unicode numeric glyphs were found outside ASCII, full-width and circled digits in
the complete NPC records; additional enclosed-number forms are regression-tested.
